# CLAUDE.md — doc/

Guidance for editing the VitePress documentation site.

## Commands

```bash
npm run doc:dev    # Dev server with hot reload (run from repo root)
npm run doc:build  # Full build: TypeDoc API generation + VitePress static site → doc_build/
npm run doc:api    # TypeDoc only — regenerates doc/api/ from source TSDoc comments
```

## Directory layout

```
doc/
  .vitepress/
    config.mts          # Nav, sidebar, site metadata — update when adding/removing pages
  guide/                # Narrative how-to pages (Typical Workflow section)
  examples/             # Complete copy-pasteable code examples
  api-overview.md       # Hand-written API overview; rewritten to api/index.md by VitePress
  contributing.md       # Contributing guide
  index.md              # Home page (VitePress "layout: home" hero + features)
doc_build/              # Build output (gitignored) — produced by doc:build
```

`doc/api/` is **auto-generated** by TypeDoc (`npm run doc:api`). Never read or edit files under `doc/api/` — they will be overwritten on the next build. Improve API documentation by editing JSDoc comments in `src/`.

## Adding a new page

1. Create the `.md` file in the appropriate directory (`guide/` or `examples/`).
2. Add a sidebar entry in `.vitepress/config.mts` under the matching sidebar key (`/guide/` or `/examples/`).
3. If the page should appear in the top nav, add it to the `nav` array too.

Both steps are required — a file without a sidebar entry is reachable only by direct URL.

## Writing style

- Sentence-case headings (`## Connection states`, not `## Connection States`).
- Short introductory sentence per section before diving into code.
- Code blocks use `typescript` language tag.
- Never have block with code only, add at least one sentence describing the snippet.
- Tables for structured comparisons (amqpx vs amqplib, option names, event names).
- Link to API reference with relative paths: `/api/index/interfaces/Consumer`.

## Sections and their purpose

| Section | Dir | Content |
|---|---|---|
| Guide | `guide/` | Narrative walkthroughs; each page covers one concept end-to-end |
| Examples | `examples/` | Self-contained copy-pasteable patterns (pub/sub, work queue, topic routing, graceful shutdown) |
| API Reference | `api/` | Auto-generated by TypeDoc; overview hand-written in `api-overview.md` |
| Contributing | `contributing.md` | Standalone page, linked from nav |

## Sidebar structure

`/guide/` sidebar has two groups: **Introduction** (what-is-amqpx) and **Typical Workflow** (topology → publishing → consuming → batch-consuming → validation → graceful-shutdown → testing).

`/examples/` sidebar has one group listing all example pages.

`/api/` sidebar is hand-maintained in `config.mts` but mirrors the TypeDoc output. When TypeDoc adds a new exported symbol, add the corresponding link under the correct group (Interfaces / Classes / Enumerations / Options & Types / namespaces).
